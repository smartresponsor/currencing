# Currencing M5: Doctrine / Entity-first hardening

M5 turns Currencing into a stable Symfony component with Doctrine as the canonical persistence model.

## Decisions

- `Currency` is the canonical Entity for stored currency metadata.
- `CurrencyCode` is a Value Object for validating and normalizing ISO-style three-letter codes.
- DTOs remain output/input contracts for UI and service results; they do not replace the Entity.
- All Doctrine tables generated by Currencing must use the `currency_*` prefix.
- The canonical currency catalog table is `currency_currency`.

## Not included

- No legacy flat `Currency/` structure.
- No FX/rate conversion logic.
- No provider adapters.
- No `/src/Domain` tree.
- No Port/Adapter split.

## Repository surface

`CurrencyRepository` exposes explicit methods for current consumers:

- `findOneByCode()`
- `findOneActiveByCode()`
- `hasActiveCode()`
- `findActiveOrderedByCode()`
- `findActiveCodesOrdered()`

## Fixture behavior

`CurrencyFixtures` is idempotent: it updates existing rows by code and persists missing rows only.
